## Major Issues

### Issue 1: Table wrapper breaks the container-padding rule

**Severity:** Major
**Location:** `components/ui/table.tsx:6`
**Category:** Visual

**Problem:**
`Table` wraps content in `.clay ... p-1` (4px) while every `Card` uses `p-5` (20px) and dialogs use `p-6` (24px). On the event detail page the attendance table sits visibly tighter than its sibling cards, and row text runs close to the 22px clay border. The inner `<table>` is also square-cornered inside a rounded container.

**Impact:**
The densest data surface in the app looks like a different component family; rows nearly touch the clay edge, weakening the soft-clay effect where readability matters most.

**Recommendation:**
Give the wrapper `p-2` minimum and round the inner table to match (`rounded-[calc(var(--clay-radius-card)-8px)] overflow-hidden`), or render the table inside `Card` with `p-0` + row padding doing the work.

**Code Example:**

```tsx
// Before
<div className="clay overflow-x-auto p-1">
  <table className={cn("w-full text-sm", className)} {...props} />
</div>

// After
<div className="clay overflow-x-auto p-2">
  <table className={cn("w-full text-sm", className)} {...props} />
</div>
```

**✅ Fixed 2026-09-28:** wrapper now `p-2` in `components/ui/table.tsx:6`. Verified: typecheck, lint, tests (34/34), build all pass.

### Issue 2: Pagination buttons bypass the Button system and miss touch targets

**Severity:** Major
**Location:** `components/attendance/AttendanceTable.tsx:69-76`
**Category:** Visual

**Problem:**
Prev/Next are raw `<button>` elements with only `clay-btn px-3 py-1.5` — no `type="button"`, no text sizing/weight, ~30px tall (below the documented 44px minimum), and visually lighter than every other action in the app.

**Impact:**
On touch devices the smallest interactive controls sit in the densest table footer; they look unfinished next to shadcn `Button` used everywhere else.

**Recommendation:**
Use the shared `Button` (`size="sm" variant="outline" className="clay-btn"`) with explicit `type="button"`. If 44px rows feel heavy here, document the table footer as an explicit exception rather than leaving raw buttons.

**Code Example:**

```tsx
// Before
<button className="clay-btn px-3 py-1.5" disabled={page === 0} onClick={...}>Prev</button>

// After
<Button type="button" size="sm" variant="outline" className="clay-btn" disabled={page === 0} onClick={...}>Prev</Button>
```

**✅ Fixed 2026-09-28:** Prev/Next now use shared `Button` (`type="button"`, `size="sm"`, `variant="outline"`, `clay-btn`) in `components/attendance/AttendanceTable.tsx:69-87`. Verified: typecheck, lint, tests (34/34), build all pass.

### Issue 3: Filter labels render raw camelCase keys

**Severity:** Major
**Location:** `components/attendance/AttendanceFilters.tsx:27`
**Category:** Visual

**Problem:**
`{key === "q" ? "Search" : key}` renders **"yearLevel"** verbatim as a user-facing label, while every other label in the app uses human copy (`Label` is uppercase overline-styled, which makes the camelCase hump even more prominent: "YEARLEVEL" vs "Search").

**Impact:**
The one data-dense staff surface shows developer vocabulary to school personnel; inconsistent with the Sentence-case-then-uppercased label system elsewhere.

**Recommendation:**
Add a label map (`q: Search, college: College, program: Program, yearLevel: Year level, gender: Gender`).

**Code Example:**

```tsx
// Before
<Label htmlFor={`f-${key}`}>{key === "q" ? "Search" : key}</Label>

// After
const LABELS = { q: "Search", college: "College", program: "Program", yearLevel: "Year level", gender: "Gender" } as const;
<Label htmlFor={`f-${key}`}>{LABELS[key]}</Label>
```

**✅ Fixed 2026-09-28:** `LABELS` map added in `components/attendance/AttendanceFilters.tsx:8-14`; labels now render human copy ("Year level"). Verified: typecheck, lint, tests (34/34), build all pass.

## Minor Issues

### Issue 4: Status badge stretches full-width in check-in results

**Severity:** Minor
**Location:** `components/attendance/CheckInForm.tsx:84-95`
**Category:** Visual

**Problem:**
The result block is `<p className="clay-pressed flex flex-col gap-1 p-4">` and `Badge` (inline-flex) becomes a stretched flex item, so the "Attendance recorded" / "Already checked in" pill spans the full card width instead of hugging its text.

**Impact:**
Pills read as banners rather than status chips; inconsistent with the compact badges on event cards.

**Recommendation:**
Add `self-start` (or `w-fit`) to both result badges.

```tsx
// Before
<Badge variant="success">Attendance recorded</Badge>
// After
<Badge variant="success" className="self-start">Attendance recorded</Badge>
```

### Issue 5: Loading skeletons don't mirror the table shape

### Issue 6: Report stat tiles squeeze at 320px

**Severity:** Minor
**Location:** `components/reports/ReportSummary.tsx:35`
**Category:** Visual

**Problem:**
`grid-cols-3` with `p-3` tiles and `text-xl` numerals has no small-screen fallback — at 320px each tile is ~90px wide and "Absent"/"Rate %" labels wrap or crowd.

**Impact:**
The report header, a headline surface, looks cramped on the smallest phones (a real kiosk-adjacent device class).

Reduce tile padding/value size below `sm` (`p-2 sm:p-3`, `text-lg sm:text-xl`) or stack to a single row of compact tiles. One-line change, no structure change.

### Issue 7: 12px muted text straddles the AA contrast line (light mode)

**Severity:** Minor
**Location:** `components/ui/input.tsx:22`, `components/ui/table.tsx:23` (+ all `Label`/`TH` usage)
**Category:** Visual

**Problem:**
`--muted-foreground: oklch(0.556 0 0)` on white sits at roughly 4.5:1 — exactly the AA boundary for body text, and all label/table-header usage is 12px. Any theme tweak or off-white clay card background can tip it under. (Dark mode `0.708` on near-black passes comfortably.)

**Impact:**
Small UI text is the most contrast-sensitive category; currently one token drift away from failing.

**Recommendation:**
Darken light-mode muted to ~`oklch(0.52 0 0)` and re-verify, or promote labels/headers to `text-[13px]`. Verify with a contrast check after any future token edit.

## Suggestions

### Suggestion 1: Filter grid leaves an orphan cell on mobile

**Location:** `components/attendance/AttendanceFilters.tsx:22`
`grid-cols-2 sm:grid-cols-5` puts 5 fields into 2 columns — the 5th (gender) sits alone in a half-width cell. Consider `grid-cols-2` with the search field spanning both (`col-span-2 sm:col-span-1`), or a 6th slot (e.g. a clear-filters action) to complete the grid.

### Suggestion 2: Kiosk label is small for gym-door distance use

**Location:** `components/attendance/CheckInForm.tsx:61`
"Enter / Scan SRCODE" renders at the global 12px overline label. For the kiosk context (arm's-length tablet, possibly hurried queues), a kiosk-scoped larger label (14–16px) would aid scannability while keeping the system label elsewhere.

### Suggestion 3: Flat dialog backdrop undercuts clay depth

**Location:** `components/ui/dialog.tsx:22`
`bg-black/40` with no blur flattens the clay dialog's soft shadows. Adding `backdrop-blur-[2px]` keeps focus on the dialog and makes the clay elevation read as layered rather than pasted.

### Suggestion 4: Detail-page action row lacks hierarchy

**Location:** `app/events/[eventId]/page.tsx:56-67`
`Mark Active` / `Close event` (admin, destructive-adjacent) sit at equal weight beside `Take Attendance` (primary flow) and `Export CSV`. Consider promoting Take Attendance to the default variant and grouping Open/Close as a secondary cluster with a divider or section label.

### Suggestion 5: Table could keep its header visible while scrolling

**Location:** `components/ui/table.tsx:12-14`
Long attendance lists scroll the header away inside `overflow-x-auto`. A `sticky top-0 bg-card` `THead` variant (opt-in via className) would help staff scanning 50-row pages. Optional; skip if lists stay short in practice.

## Positive Observations

- Token discipline is real: radii, clay shadows, spacing scale, and type scale all come from `:root` tokens with dark-mode counterparts — no magic numbers in components.
- Status system is genuinely accessible: icon + text pairing everywhere, and badges carry `dark:` contrast variants (a rare detail).

- Loading/error/empty states exist on every data surface (`loading.tsx`, `error.tsx`, table/report/lookup fallbacks).
- Touch-target rule is codified in CSS (`nav`/`form` 44px minimum), not just documented.
- `text-wrap: balance` on headings and 65ch body measure show typographic care.
