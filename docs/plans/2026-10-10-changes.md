# Changes — 2026-10-10 batch

Built and verified, **not yet deployed**. Production still runs the pre-batch
code and data paths; every behavior below is flag- or deploy-gated. Commits
`d8e844b` → `fce6e61` on `main` (plus uncommitted: none — tree is clean).

## 1. Offline hydration crashes fixed

**Symptom:** opening event pages sometimes threw "Hydration failed …
server rendered HTML didn't match the client" and re-rendered from scratch.

**Cause:** two components read browser-only state during render, so the
server and the browser drew different first HTML — the offline banner (via
`navigator.onLine`) and the queue panel (via IndexedDB presence).

**Change:** both now render the same neutral first frame on server and
client, then sync the real value after hydration. No visual change.
Files: `hooks/useOnline.ts`, `components/offline/QueueSyncPanel.tsx`.

## 2. One-click PDF download

**Before:** "Download PDF" just opened the print dialog (same as Print).

**Now:** it builds a real `.pdf` file in the browser and downloads it as
`{eventId}-attendance-report.pdf` — no dialog. Content mirrors the print
preview exactly: legal landscape, 1.27cm margins, 1pt black grid, Times
10pt, 12/30/14/44 columns, centered seal + letterhead row (seal 80pt,
lifted ~4mm), red footer motto per page. Shared constants keep PDF and
print from drifting; print itself is untouched.
New deps: `jspdf`, `jspdf-autotable` (client-side, works offline).
Files: `lib/reports/pdf.ts`, `components/reports/DownloadPdfButton.tsx`,
print page wiring.

## 3. Neon migration (database live, traffic not)

A Neon Postgres project (`Atty`, Singapore) now holds verified copies:
**1036 students, 7 events, 18 attendance rows** on `production`,
plus a disposable `dev` branch for testing. Apps Script is demoted to
flag-flip backup — still deployed, still tested.

**Cutover switches** (each `neon` = Neon, anything else = Sheets; all
default to Sheets, so behavior is unchanged until flipped):

| Flag | Area moved | Effect when on |
|---|---|---|
| `NEON_STUDENTS` | Student lookup | Indexed PK lookup + 5-min repeat cache |
| `NEON_EVENTS` | Event list/view/create/update/open/close | Indexed queries, same rules and error messages |
| `NEON_ATTENDANCE` | Check, record, list, report | Validation + writes in Neon; duplicates rejected by the database itself |

Validation got structurally faster, not just relocated: event and student
reads run concurrently, and record is validate → single guarded insert.
Error contracts (`SRCODE_NOT_FOUND`, `DUPLICATE_ATTENDANCE`,
`EVENT_NOT_ACTIVE`, …) are identical under both backends.
Files: `integration/neon.ts`, flag branches in `integration/{students,
events,attendance,reports}.ts`.

## 4. Nightly + manual Sheets backup

Since Neon is about to become primary, the spreadsheet becomes its mirror:
every night at 2am PHT (plus a **Back up to Sheets** button on the
dashboard) events and attendance copy Neon → Sheets. Merge-only: new rows
append, changed rows update in place, hand-typed rows are counted but
**never deleted**. Empty events are skipped, never wiped. Timestamps are
normalized to sheet format (Manila) on write, healing older ISO rows on
first pass. Students excluded (yearly roster, separate ritual).
Needs: `CRON_SECRET` env var, Apps Script redeployed with `backup.gs`.
Files: `apps-script/backup.gs`, `integration/backup.ts`,
`app/api/admin/backup/route.ts`, `components/admin/SheetsBackupButton.tsx`,
`vercel.json`.
