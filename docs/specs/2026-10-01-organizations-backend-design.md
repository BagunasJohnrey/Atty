# Organizations Backend — Design

**Date:** 2026-10-01
**Status:** Approved
**Scope:** Backend only. No `page.tsx`, no components, no report letterhead changes.

## Purpose

Organizations are the entities that use the attendance tracker. Today the
report letterhead in `app/(app)/events/[eventId]/report/print/page.tsx:57-126`
hardcodes a single school's identity, and the event's Time field on that same
report is a blank underline (line 118). Neither can be changed without a code
edit and redeploy.

This change introduces organizations as a real entity in the backend, links
events to them, and adds a free-text event time range in the format the PDF
report needs (`12:00 pm - 5:00 pm`). A later frontend task renders these on the
report and links the organization name to a report view.

`docs/authentication.md:5` currently describes the app as "single-tenant." That
is no longer accurate once events carry an owning organization, so the spec
keeps the auth model unchanged — there is still exactly one admin credential —
and only the data model becomes multi-org. The single-tenant note in the docs
is corrected as part of this work.

## Decisions

| Decision | Choice | Rationale |
| --- | --- | --- |
| Org cardinality | Multiple orgs, each owning events | An org is the customer of the tracker; several schools can use one deployment. |
| Letterhead fields | Org owns name, email, address, phone, website | Everything needed to replace the hardcoded letterhead without another code change. |
| Event fields | Event owns date, time range, location | Time range is per-event; it cannot live on the org. |
| Time storage | Single free-text string, verbatim | The PDF prints the string as typed. Parsing it into start/end introduces timezone and 12-hour formatting bugs for no benefit. |
| Org list | `GET /api/organizations`; name is plain data | The endpoint serves the records a future org-name link needs. The link itself is frontend work. |
| Events without an org | `orgId` optional on create, validated when supplied | `components/events/EventFormDialog.tsx:22-27` posts no `orgId`. Requiring it would break the New Event form, and fixing that is a frontend change this spec excludes. |
| Print page | Untouched | Explicitly out of scope. The letterhead stays hardcoded until the frontend task. |

## Storage

### Organizations sheet

New sheet, defined in `apps-script/config.gs`.

| Index | Header | Required | Max length |
| --- | --- | --- | --- |
| 0 | Org ID | yes | generated |
| 1 | Org Name | yes | 150 |
| 2 | Email | no | 150 |
| 3 | Address | no | 200 |
| 4 | Phone | no | 60 |
| 5 | Website | no | 200 |
| 6 | Deleted | no | soft-delete stamp |

`ORG-001`, `ORG-002`, … generated by scanning existing IDs for the max numeric
suffix, under the same script lock `Events.create` uses (`events.gs:83-93`).
The scan includes soft-deleted rows: an ID is spent once assigned, so reusing
`ORG-007` would give two organizations the same ID and make `getById`
ambiguous.

### Soft delete

`Deleted` holds a timestamp string, or `""` when active. Any non-empty value
counts as deleted — Sheets may coerce a timestamp to a number, so truthiness is
the test rather than the type.

The two read paths deliberately disagree:

| Path | Includes deleted | Why |
| --- | --- | --- |
| `Organizations.all()` | no | A picker or list must not offer a deleted organization. |
| `Organizations.getById()` | yes | A report letterhead must keep resolving one. |

This is the whole reason delete is soft. A hard delete would either break every
event referencing the organization or silently orphan them, and a letterhead
that resolved to nothing would reprint as the default — a quietly wrong
document, filed for an event that already happened. Keeping the row means
deleting an organization never rewrites history.

`assertOptional` also resolves deleted organizations, so an event whose
organization was deleted can still be edited. Otherwise every patch on that
event would revalidate the reference and fail, stranding the event with no way
to change even its time.

Both operations are idempotent, and a second delete preserves the original
stamp so the recorded time of deletion stays the first one.

### Events sheet additions

Two new **trailing** columns.

| Index | Header | Max length |
| --- | --- | --- |
| 7 | Org ID | 20 |
| 8 | Time | 100 |

Trailing is required, not cosmetic. `Sheets.ensureHeaders`
(`apps-script/sheets.gs:103-119`) only fills columns that are `undefined` or
blank at their index, so a non-trailing insert would overwrite live data.

The header row gains the labels on the next event creation, because
`Events.nextIdAfterEnsuringRegistry` (`events.gs:102-104`) is the only path
that calls `ensureHeaders` for the Events sheet. Before that happens,
`row[7]` and `row[8]` are `undefined` and `Models.eventFromRow` maps them to
`""`. Legacy events therefore read as `orgId: ""`, `time: ""` with no
migration step and no forced `ensureHeaders` read on the hot path — a forced
read would add a `getRange` call to every `Events.getById`, and
`apps-script/checkin-cost.test.ts:187-200` budgets the check-in path at 20 read
calls total.

### Time format

Stored and returned verbatim. `"12:00 pm - 5:00 pm"` in, the same string out.
No parsing, no normalization, no timezone handling. Validation is a
length cap only, via `Validators.optionalString`. An empty value is allowed,
matching how `location` and `description` behave today.

### `models/event.ts` (amended)

`SchoolEvent` gains `orgId: string` and `time: string`, both required on the
read model and always present (empty string when unset). `CreateEventInput`
and `UpdateEventInput` gain optional `orgId?: string` and `time?: string`.

Making the two read-model fields required rather than optional is deliberate:
it forces every consumer to decide what an absent org means, and it keeps the
frontend task from having to widen a type it did not write.

### `models/api.ts` (amended)

- `OrganizationsResponse = ApiSuccess<{ organizations: Organization[] }>`
- `OrganizationResponse = ApiSuccess<{ organization: Organization }>`
- New `API_ERROR_CODES.ORG_NOT_FOUND: "ORG_NOT_FOUND"`

`ORG_NOT_FOUND` must land in three places, which the codebase already keeps in
lockstep: `apps-script/responses.gs:27`, `models/api.ts:41`, and
`UPSTREAM_STATUS_BY_CODE` in `lib/api.ts:103` — mapped to **404** there, next
to `EVENT_NOT_FOUND`.

## Backend

### `apps-script/organizations.gs` (new)

Mirrors `apps-script/events.gs` structure:

- `all()` — returns `[]` when the sheet is absent, matching `Events.all`
  (`events.gs:12`), so a fresh spreadsheet does not throw on first read.
- `getById(id)` — one bulk read, in-memory scan.
- `assertById(id)` — throws `AppError(ORG_NOT_FOUND)`.
- `create(input)` — script lock, generate ID, `ensureHeaders`, append row.
- `update(id, patch)` — only keys present in the patch are written.
- `nextId()` — max numeric suffix scan.
- `handleList`, `handleGet`, `handleCreate`, `handleUpdate` — action handlers
  returning `Responses.ok`.

### `apps-script/models.gs` (amended)

- New `Organization` JSDoc typedef, alongside the existing three at lines 9-39.
- New `organizationFromRow(row)` following `eventFromRow` (line 54).
- `eventFromRow` gains `orgId` (index 7) and `time` (index 8). Both use
  `String(row[...] || "")` so a pre-migration sheet yields `""`.

### `apps-script/events.gs` (amended)

`create` takes `orgId` and `time` and appends them at indices 7 and 8.
`update` accepts `orgId` and `time`; `orgId` is checked with
`Organizations.assertById` **only when non-empty**, so a blank value stores as
`""` and a typo'd value throws. `handleUpdate`'s `allowed` array at line 284
gains `"orgId"` and `"time"` — it rejects unknown keys by design, so without
this a PATCH with `orgId` would fail.

The event `create` path also validates `orgId` when supplied, using the same
conditional check.

### `apps-script/Code.gs` (amended)

Four router entries at line 47:

```
getOrganizations: Organizations.handleList,
getOrganization: Organizations.handleGet,
createOrganization: Organizations.handleCreate,
updateOrganization: Organizations.handleUpdate,
```

### Check-in read budget

Unchanged. Org validation lives only in `Events.create` and `Events.update`.
`Attendance.check` and `Attendance.record` never touch the Organizations
sheet, so `checkin-cost.test.ts` keeps passing at 10 Events reads for 5
students and ≤20 total calls.

## API routes

### `app/api/organizations/route.ts` (new)

- `GET` -> `getOrganizationsCached()`, wrapped in `cachedJson(..., 30)`. Active rows only.
- `POST` -> `parseJsonBody`, `requireString(body, "name", 150)`, four
  `optionalString` calls, then `createOrganization` and `expireOrganizations()`.
  Returns **201**.

### `app/api/organizations/[orgId]/route.ts` (new)

- `GET` -> `getOrganizationCachedFor(orgId)`, `cachedJson(..., 30)`. Resolves a
  soft-deleted organization.
- `PATCH` -> `parseJsonBody`, field allowlist mirroring
  `app/api/events/[eventId]/route.ts:13-19` and its `parsePatchBody` helper
  (lines 61-89), then `updateOrganization` and `expireOrganization(orgId)`.
- `DELETE` -> `deleteOrganization`, then `expireOrganization(orgId)`. Soft.

### `app/api/organizations/[orgId]/restore/route.ts` (new)

- `POST` -> `restoreOrganization`, then `expireOrganization(orgId)`.

A named subroute rather than a second verb on the item, matching how
`openEvent` is `POST /api/events/[eventId]/open`: a state transition gets its
own name so the call site reads as what it does.

Every handler in these files uses the standard template: `export const dynamic =
"force-dynamic"`, `params` as `Promise<{ orgId: string }>`, and the handler body
wrapped in `respondWith` with `await requireAdmin()` as its first statement.

`lib/auth/cache-isolation.test.ts:59-76` requires **one `await requireAdmin()`
per exported handler**, so `organizations/route.ts` needs two (GET and POST),
`organizations/[orgId]/route.ts` needs three (GET, PATCH, DELETE), and
`organizations/[orgId]/restore/route.ts` needs one (POST).

### Event routes (amended)

- `app/api/events/route.ts` POST reads optional `orgId` (20) and `time` (100).
- `app/api/events/[eventId]/route.ts` `UPDATABLE_FIELDS` at line 13 gains
  `orgId` and `time`, and its error message at line 85 lists them.

## Out of scope

Explicitly excluded, per the request for backend-only work:

- `app/(app)/events/[eventId]/report/print/page.tsx` — keeps the hardcoded
  letterhead (lines 57-126) and the blank Time underline (line 118).
- `components/events/EventFormDialog.tsx` — no org select, no time input.
- Any new page, component, or `SideNav` entry.
- `lib/api-client.ts` — no client-side org functions. They belong to the
  frontend task, alongside the components that would call them.

## Testing

TDD per the repo's documented expectation (`docs/testing.md`). Vitest.

**New `apps-script/organizations.test.ts`** — reuse the `node:vm` harness
pattern from `attendance.test.ts:44-231`, seeding an `Organizations` sheet.
Covers: list returns rows; get by ID; create assigns the next sequential ID;
create rejects a duplicate; update patches only supplied fields; unknown org
throws `ORG_NOT_FOUND`; missing sheet returns `[]` rather than throwing.

**Amend `attendance.test.ts` and `checkin-cost.test.ts`** — add
`organizations.gs` to `LOAD_ORDER` / `FILES`, and to the seed data. The
attendance assertions themselves must not change; they are the regression
guard for the read budget.

**New `integration/organizations.test.ts`** — mock `requestAppsScript` per
`integration/events.test.ts:13-17`, assert the action name and params for all
four functions, and that missing optional fields default to `""`.

**Amend `integration/events.test.ts`** — `sampleEvent` gains `orgId` and
`time`; add a case that `createEvent` forwards an `orgId` when given.

**Unchanged but must pass:** `lib/auth/cache-isolation.test.ts`. It is a
structural guard that reads route source text, so it will fail the build if a
handler is missing its `requireAdmin()`.

## Acceptance criteria

1. `npm test` passes, including the read-budget suite with unchanged numbers.
2. `npm run typecheck` and `npm run lint` pass.
3. `GET /api/organizations` returns created orgs with all six fields.
4. `POST /api/events` with a valid `orgId` stores it; with a bogus one returns
   404 `ORG_NOT_FOUND`; with none it stores `""`.
5. `PATCH /api/events/EVT-001` with `{"time":"12:00 pm - 5:00 pm"}` returns the
   event with that exact string.
6. `GET /api/events` and `GET /api/events/EVT-001` include `orgId` and `time`
   on every event, `""` when unset.
7. An event created before this change still reads, reports, and accepts
   attendance.
8. No file under `app/(app)` or `components` is modified.
